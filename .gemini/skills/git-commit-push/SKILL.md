# Git Commit & Push Skill

Универсальный навык для создания стандартизированных коммитов по спецификации **Conventional Commits** и их безопасной отправки в удаленный Git-репозиторий. Подходит для любых проектов и стеков (Backend, Frontend, QA Automation, DevOps).

---

## Стандарт сообщений коммита

Все коммиты формируются в однострочном формате на английском языке в нижнем регистре:

```text
<type>(<scope>): <short description in lowercase English>
```

### Основные типы (`type`):
- `feat` — новая функциональность (эндпоинт, компонент, фича).
- `fix` — исправление ошибки, бага или визуального дефекта.
- `refactor` — изменение структуры кода без изменения его поведения.
- `style` — форматирование кода, отступы, линтеры (Google Style, Spotless, Prettier).
- `docs` — изменения в документации, README, комментариях.
- `test` — добавление или правка тестов.
- `build` — изменения в сборщике и зависимостях (Maven `pom.xml`, Gradle, npm `package.json`, Dockerfile).
- `ci` — изменения в CI/CD пайплайнах (GitHub Actions, GitLab CI).
- `chore` — вспомогательные задачи, обновление `.gitignore`, конфигов.

### Область (`scope`):
Указывается в скобках опционально, обозначает затрагиваемый модуль или компонент (например: `api`, `ui`, `auth`, `docker`, `readme`, `cache`).

### Требования к тексту (`description`):
- Язык: **английский** (English).
- Регистр: строго **нижний регистр** (lowercase), без точки на конце.
- Глагол в повелительном/настоящем времени (*add, update, fix, remove, redesign, configure*).
- Длина всей строки: до **72 символов**.

## Пошаговый алгоритм

1. **Проверить статус изменений:**
   ```bash
   git status -s
   ```
   *Если изменений нет — сообщить пользователю и завершить работу.*

2. **Оценить список файлов:**
   ```bash
   git diff --stat
   ```
   *Убедиться, что в изменения не попадают секреты (`.env`, приватные ключи).*

3. **Сгенерировать сообщение коммита:**
   На основе изменённых файлов сформулировать сообщение по стандарту Conventional Commits.

4. **Запросить подтверждение у пользователя:**
   Вывести текущую ветку, краткую статистику файлов, предложенное сообщение коммита и спросить подтверждение.

5. **Выполнить коммит и пуш:**
   После получения согласия пользователя выполнить:
   ```bash
   git add -A
   git commit -m "<type>(<scope>): <description>"
   git push
   ```
   *(Если у ветки ещё нет upstream: `git push -u origin <branch>`)*.

---

## Правила безопасности

- **Никаких `git push --force`:** силовые пуши запрещены.
- **Никаких `git commit --amend`** без прямого запроса пользователя.
- **Не коммитить секреты:** игнорировать и не индексировать файлы `.env`, пароли, ключи и временные папки сборки.
